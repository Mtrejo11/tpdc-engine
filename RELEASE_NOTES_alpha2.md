# TPDC v0.2.0-alpha.2

**Bug-fix release driven by real-world dogfooding.**

After tagging `v0.2.0-alpha.1`, we ran TPDC v2 against a real personal repo (`Mtrejo11/inventario-reventa`) with the deliberately vague task *"Mejorar la UI de los action buttons de la card de producto"*. The smoke surfaced **5 bugs** the synthetic smoke tests had missed. This release fixes all of them.

---

## What broke during dogfooding

The agent halted at `max_turns_exceeded` after 30 turns / 37 tool calls / **527k input tokens** — without committing, without opening a PR, without leaving any draft work behind. The pipeline correctly halted, but the result was an expensive no-op (~$1.61) and the agent's partial-but-coherent code changes were stranded in an orphan worktree.

Five distinct gaps surfaced. All are addressed below.

---

## Fixes

### 🔴 #1 + 🟢 #5 — Turn budget + over-reading
**Symptom:** `max_turns_exceeded` after 30 turns; tokens-in:tokens-out ratio of 75:1 (vs ~25:1 in synthetic smokes), suggesting the agent spent most of its budget reading files instead of writing them.

**Fix:**
- `DEFAULT_MAX_TURNS`: 30 → **60** (configurable per request via `maxTurns?: number`).
- System prompt rewritten: *"Locate first, read second, write third"*. Prefers `grep`/`find` over `ls` for navigation; explicitly excludes `node_modules`, `dist`, `build`, lock files; targets single-digit `view` calls before the first edit.

### 🟡 #4 — Lost partial work on halt
**Symptom:** when the agent ran out of turns, three modified files (a coherent partial change) sat in a worktree directory with no commit, no branch on the remote, no PR. Game over.

**Fix:** the workflow now has a **WIP recovery path**:
1. If `execute.status === "max_turns_exceeded"` AND files were changed → commit as `WIP: <intake.title>` (the agent's work is preserved as a real commit).
2. Skip `run-tests` + `wait-CI` + `auto-fix` (validating incomplete work is meaningless and would just churn).
3. Push the branch and open a **draft PR** with a `⚠️ Work in progress` warning at the top.
4. Final workflow status: `{ status: "completed", stage: "wip-pr-opened" }`.

A human reviewer can now pick up where the agent stopped instead of seeing nothing.

### 🟡 #2 — `finalSummary` invisible on halt
**Symptom:** the agent's last words (its own summary of what it did and why it stopped) never made it to logs or the workflow return value, so debugging halts required SSH-ing into Inngest internals.

**Fix:** `logger.info("Execute complete", { ..., finalSummary })` now includes a 500-char preview. Halt return objects also surface it.

### 🟡 #3 — No mid-flight observability
**Symptom:** while execute was running (which can take 5+ minutes on a real repo), the only way to know if the agent was making progress vs stuck was to manually `ls` the worktree directory.

**Fix:** new event `tpdc/execute.tool_call` is emitted **once per tool invocation**:

```ts
{ runId, turn, toolName, toolInputPreview, phase: "initial" | "fix" }
```

Each event is visible in the Inngest UI's events tab in real time. Errors thrown by the observability callback are swallowed — observability never breaks the agent loop.

## Compatibility

- **No breaking changes.** All `ExecuteRequest` and `OpenPRRequest` additions are optional fields.
- New event `tpdc/execute.tool_call` is purely additive (existing event handlers unaffected).
- Default `maxTurns` change (30 → 60) is conservative for React-scale repos and slightly costlier in worst-case scenarios. If you need the old behaviour, pass `maxTurns: 30` in `ExecuteRequest`.

---

## Tests

145 unit tests pass (was 140 in alpha.1). New coverage:
- `body-template.test.ts` — 4 new tests for the WIP rendering path.
- `open-pr.test.ts` — 1 new test confirming `wipReason` + `--draft` make it to gh CLI.

Integration tests for stages that hit Anthropic API remain gated behind `ANTHROPIC_API_KEY` (skipped by default).

---

## Known limitations carried forward

The `What's NOT in v2 alpha` section from the alpha.1 release notes still applies. Of particular note:
- Auto-fix loop (local + CI) **still hasn't been exercised in production** — both smokes that reached run-tests passed at first try. Unit tests with mocks cover the code path.
- The MAX_TURNS bump is a heuristic, not a fundamental fix. Repos larger than `inventario-reventa` may still hit the new ceiling. The `maxTurns?` override exists for that escape hatch.
